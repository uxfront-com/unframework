# ADR-0040: SVG is lowered inside `<svg>`, with case-exact tables checked against the parsers

- **Status:** Accepted
- **Date:** 2026-10-05
- **Plan:** §4.3, §5.3, §7.5, §9 M1; P2, P4, P5; ADR-0030, ADR-0031, ADR-0037, ADR-0038;
  amends ADR-0032

## Context

M0 reports `<svg>` and `<math>` once, as UF1002, and skips their content. ADR-0032 requires every
tag to be an HTML element and every attribute an HTML attribute of its element, and the IR's schema
patterns are lower case. M1 lowers SVG (§9), which breaks each of those assumptions:

- SVG names are case-sensitive (`viewBox`, `linearGradient`). The HTML parser adjusts a fixed set
  of them in foreign content and lower-cases the rest, while a client's `setAttribute` keeps the
  case as written, so SSR and the client can disagree.
- The HTML parser leaves SVG when it meets `div`, `p`, `span`, `b` and other HTML tags, so an HTML
  element inside `<svg>` parses differently on the server and the client. It also reads the
  element children of SVG's `<title>`, `<desc>` and `<foreignObject>` as HTML, and so does Vue's
  compiler, where React keeps them in SVG.
- Tag-keyed tables collide: SVG has its own `a`, `title`, `script` and `style`. An SVG `<title>`
  renders, where React hoists an HTML one.
- Svelte drops whitespace-only text everywhere in SVG except inside `<text>`.
- Vue's template compiler gives a root `<path>` the HTML namespace, so a component whose root is an
  SVG child renders in the wrong namespace there. Solid's compiler creates a `<title>` that starts
  a template in HTML's namespace, and an `<a>` as an HTML link.
- The frameworks' element types disagree on SVG too: Vue and React type SVG's `<title>` with
  HTML's attributes.

## Decision

- **The namespace is derived, not stored.** `<svg>` starts the SVG namespace, and everything inside
  it is SVG (`elementNamespace` in `@unframework/ir`). MathML is UF1002, reported once with
  nothing inside analysed (a `<math>` inside `<svg>` is UF3001). `foreignObject` is UF1002 in M1,
  reported the same way.
- **Elements come from `SVG_ELEMENTS`** (`@unframework/ir`): the SVG elements the vendored JSX
  types list that Vue's `isSVGTag` also knows, with `title`, which the vendored types type as
  HTML's. Left out: `feDropShadow`, which the HTML parser (parse5 8) does not restore from
  `fedropshadow`, so the server's markup and a client's DOM differ in case; and the elements no
  component can render (`SVG_UNRENDERABLE_ELEMENTS`): `script` and `style`, which Vue and Angular
  drop, and SMIL's `animate`, `animateMotion`, `animateTransform`, `set` and `discard`, which can
  set an `href` at run time and make the rendering depend on time (UF3002), and `foreignObject`
  (UF1002). Every entry matches the tag pattern.
  - An HTML element inside `<svg>` is UF3001, with the help to close the `<svg>` first; an
    SVG-only element outside it is UF3001 with the help to put it inside one; a tag in the wrong
    case is UF3001 with a safe rename.
  - SVG's `<a>` is UF1002: Vue's `isSVGTag` does not know it, and Solid creates it as an HTML
    link. It lands with a later milestone.
  - A component whose root is an SVG child (`<g>`) is UF1002 until M3.
- **Attributes are case-exact**, from `SVG_GLOBAL_ATTRIBUTES` (`class`, `id`, `lang`, `role`,
  `style`, `tabindex` and SVG 2's presentation attributes, as the vendored types spell them) and
  `SVG_ELEMENT_ATTRIBUTES` (each element's own, from SVG 2 and Filter Effects 1, that the vendored
  types know). Left out: the presentation attributes SVG 2 deprecates, the conditional processing
  attributes (`systemLanguage` makes the rendering depend on the reader's language), the
  attributes SVG 2 removes, camel-case names the HTML parser does not restore, and `crossorigin`.
  ARIA and `data-*` work as in HTML. A name in another case, or React's camel case (`viewbox`,
  `strokeWidth`), is UF3004 with a safe rename.
  - SVG has no boolean attributes, so a bare SVG attribute is UF3004, with a likely fix to
    `=""`; ARIA's true/false states and `data-*` still mean `"true"` bare (ADR-0030).
  - `xlink:href` is UF3004 with a safe fix to `href` when `href` is not set; other `xlink:`,
    `xml:` and `xmlns` names are UF3005. The URL rules apply to SVG's `href`.
  - **The descriptive elements, `<title>` and `<desc>`, take only `class`, `id`, `lang` and
    `style`**, with ARIA and `data-*` (`SVG_DESCRIPTIVE_ATTRIBUTES`): they render nothing a
    presentation attribute could style, and Vue types `<title>` with HTML's attributes, so one
    fails vue-tsc (L4).
- **Text in SVG.** Whitespace-only text is UF3003 with a safe removal fix, except inside a `<text>`
  element and everything in it, where Svelte keeps it: so it is UF3003 in a `<tspan>` outside a
  `<text>`, and in `<title>` and `<desc>`. In those text elements it has no fix, as it may separate
  two values of an accessible name or description (`<title>{label} {status}</title>`), which
  removing it would change; the help writes the values and the space as one template expression,
  ``<title>{`${label} ${status}`}</title>``, whose text Svelte keeps. Static text is accepted in any
  SVG element. An Interpolation, or a conditional that renders text, may sit only in `text`,
  `tspan`, `textPath`, `title` and `desc` (`SVG_TEXT_ELEMENTS`, UF3003). `<title>` and `<desc>` hold
  no elements (UF3003): the parser and Vue would read them as HTML.
- **An SVG `<title>` that starts a conditional's branch or a list's element is UF1002**: Solid
  creates it in HTML's namespace there, where it titles nothing. The help is to wrap it in a `<g>`,
  or render it always.
- **Printing.** A childless SVG element self-closes in every output (`<circle … />`), except on
  Svelte for an element whose name is also an HTML element's: Svelte tells SVG from HTML by tag
  name, and its SVG list lacks `title`, so `<title />` warns `element_invalid_self_closing_tag`
  (L3), and the Svelte output writes `<title></title>`. React writes SVG's attributes in its own
  camel case (`strokeWidth`, `stopColor`); Qwik, Solid and the markup targets keep SVG's names. An
  SVG `<title>` needs its own spelling on four targets:
  - React's server renderer writes a title's text only when its children are one value, so the
    React output gives a title of several parts (text, interpolations, conditionals) one child: a
    template literal (``<title>{`${label} (${state})`}</title>``);
  - Qwik types a `<title>`'s child as `string`, in SVG as in HTML, so several children, a number,
    `null` or JSX fail L4. A text, or a value certainly `string` or `undefined`, stays as written;
    several parts are one template literal; a conditional alone is a ternary chain of strings
    ending in `undefined`; a prop that may be `null` is `value ?? ""`; a number is
    `` `${count}` ``;
  - in both, a part takes `?? ""`, so that a nullish one renders nothing, only where TypeScript
    reads it as sometimes nullish, by its own syntactic rule: `??`, `=`, `??=` and the comma by
    their right operand, a conditional by both branches, `||`, `&&`, a read and a call as
    sometimes, literals and operators as never. TypeScript rejects `??` on a value that is never
    or always nullish (TS2869, TS2871), so a nullish `??` fallback is written `""`, and a part
    always nullish is left out. The helpers are shared (`packages/codegen/src/js/text.ts`);
  - Angular's lexer reads a `<title>`'s content as text, blocks included, unless the tag itself
    names the SVG namespace, so the Angular output writes `<svg:title>`;
  - Astro keeps the whitespace inside a `<title>`, whose content is text in every namespace, so
    the markup printer keeps a title's content on its tag's line.

  Solid writes the presentation attributes its types lack on an element (gradients, filter
  primitives, `<stop>`) as an object spread (ADR-0037). Bound SVG attributes follow ADR-0037, and
  numbers in an SVG `style` follow `UNITLESS_PROPERTIES` (ADR-0038), so `style={{ strokeWidth: 2 }}`
  is UF3018: react-dom writes the number bare there and Qwik adds `px`, so the likely fix writes
  `"2"`, as React renders it; the `stroke-width="2"` attribute is unaffected.

- **The capability `svg`** (any `svg` element, reported at the first) is native on all seven
  targets.
- **Amendments to ADR-0032.** A tag is an HTML element, or, inside `<svg>`, an `SVG_ELEMENTS`
  entry; HTML elements never sit inside `<svg>`, and no element inside an SVG `<title>`, `<desc>`
  or `<foreignObject>`. An attribute is an HTML attribute of its element or, in SVG, one from the
  SVG tables, with no `true` value. Whitespace-only text appears in SVG only inside a `<text>`;
  interpolations and conditional text only in `SVG_TEXT_ELEMENTS`; an SVG `<title>` never starts
  a branch or a list's element. The HTML-only rules (void elements, the leading line feed,
  `textarea`, numeric forms, boolean bindings) apply in the HTML namespace only. The schema's tag
  and attribute-name patterns accept upper case; the case-exact tables, checked by the
  invariants, decide what is valid.

## Consequences

**Positive:**

- Inline icons, the common SVG in components, render the same DOM, in the SVG namespace, on seven
  targets, from SSR and from the client.
- The tables are tested against parse5, Vue and the vendored types, so a new SVG name is a table
  change with an oracle, not a guess.

**Negative:**

- `foreignObject`, SMIL animation, MathML, SVG links and a component rooted in an SVG child are not
  available in M1.
- Whitespace between SVG elements must be left out of the source: formatted JSX keeps none anyway,
  but hand-written spaces are rejected.
- A `<title>` cannot be conditional on its own, and `<title>` and `<desc>` take few attributes.

**Open:**

- M3: SVG-child roots, which need the parent's namespace to reach the child's output (Svelte's
  `<svelte:options namespace="svg">`, Angular's `:svg:` prefix).
- `foreignObject` needs the namespace to switch back to HTML in every printer and in the
  invariants.
- SVG links, once Vue and Solid can render them.

## Alternatives considered

- **A stored `namespace` field on elements.** Targets would not re-derive it, but it is redundant
  with the tree, and an invariant would have to check that the two agree (P5: a field only when a
  consumer needs it).
- **Accept `xlink:href` beside `href`.** Two spellings of one attribute (P3); frameworks differ on
  `setAttributeNS`, and the normaliser compares attribute namespaces.
- **Lower-case SVG names as HTML does.** `viewBox` would then fail on every client that keeps case.
- **Every SVG attribute on `<title>`, as the SVG types allow.** Vue's and React's types reject them
  there, and they style nothing.

## Evidence

- Svelte 5.57.1 removes whitespace-only text in SVG unless a `text` element is an ancestor
  (`can_remove_entirely` in its transform utilities).
- React 19.3 hoists nothing in SVG context, so an SVG `<title>` renders in place. But its server
  renderer (`pushTitleImpl`) writes a title's text only when the title's children are one value:
  for an array it writes an empty `<title></title>` and warns, and the client's text then fails
  hydration. `packages/codegen/test/markup.test.ts` "writes an SVG title as Angular reads its
  blocks, on one line" pins the Angular and Astro spellings, and
  `packages/target-react/test/emit.test.ts` the React one: "joins an SVG <title>
  of several parts into one string, in branches and lists too", "renders an SVG <title> of
  several parts as their text, nullish parts as nothing" and 'type-checks a joined <title>, with
  `?? ""` only where TypeScript allows it (L4)'. `packages/target-qwik/test/emit.test.ts` "joins a
  title of several parts into one string, in branches and lists too" and `test/typecheck.test.ts`
  "type-checks every form the target writes a title in" pin Qwik's. The corpus case
  `jsx/svg-titles` exercises them on all seven targets.
- Vue's template compiler gives a root `<path>` and a `<b>` inside an SVG `<title>` the HTML
  namespace. dom-expressions (Solid) leaves `title` and `a` out of its SVG element list.
- Vue 3.5.43's `isSVGTag` lists `color-profile`, which does not fit the tag pattern; the vendored
  types list no hyphenated SVG element, so the intersection needs no exclusion for them.
- `packages/analyzer/test/m1-conformance.test.ts`, "the SVG vocabulary": "is the vendored types'
  SVG elements (with <title>) that Vue knows", "keeps each element's case through the HTML
  parser", "keeps each attribute's case through the HTML parser, and the vendored types declare
  it", and "is accepted by the analyser, each element in an <svg>". They pin the tables to
  parse5 8.0.1's adjustment tables, Vue's `isSVGTag` and the vendored `SVGAttributes`.
- `packages/analyzer/test/svg.test.ts` holds the rules: "reports <math> once, and nothing inside
  it", "reports a <foreignObject> once, and nothing inside it", "renames the SVG attribute in %s",
  "offers no rename to an href already set", "keeps static text in any SVG element, as every
  target does", "reports an SVG <title> that starts a branch or a list's element", "reports
  whitespace between values in an SVG <title>, without a fix that removes it". The IR's
  `invariants.test.ts` breaks each amendment ("whitespace in an SVG title", "a javascript: URL on
  an SVG element", …) and accepts "whitespace in SVG text and its spans".
- The render-parity kit's attribute sweep "renders every SVG element and SVG's attributes in an
  <svg>, with their case" through each framework (`packages/codegen/test/render-parity.test.ts`).
- Qwik 2.0.0-beta.47 renders `style={{ strokeWidth: 2 }}` as `stroke-width:2px`; React and Vue
  render `stroke-width:2`.
- `packages/target-svelte/test/emit.test.ts` "closes childless SVG elements, but for a `<title>`,
  and keeps a root fragment's text", and "emits %s so Svelte compiles it without a warning,
  formatted or not" over the same shape.
- `normalizeDom` (`packages/testing/src/dom/serialize.ts`) throws on an SVG child created in the
  HTML namespace (`dom.browser.test.ts`, "rejects an SVG child created in the HTML namespace,
  which renders nothing"), so a target that gets the namespace wrong fails L7.
- `jsx/svg` is green at every live layer on all seven targets. The L10 canaries reach its `<svg>`
  root: `L10-root-hidden` hides a root with a `display: none` declaration, since an `<svg>` takes
  no `hidden`.
