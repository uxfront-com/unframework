# ADR-0040: SVG is lowered inside `<svg>`, with case-exact tables checked against the parsers

- **Status:** Accepted
- **Date:** 2026-10-02
- **Plan:** §4.3, §5.3, §7.5, §9 M1; P2, P4, P5; ADR-0030, ADR-0031, ADR-0037, ADR-0038;
  amends ADR-0032

## Context

M0 reports `<svg>` and `<math>` once, as UF1002, and skips their content. ADR-0032 requires every
tag to be an HTML element and every attribute an HTML attribute of its element, and the IR's schema
patterns are lower case. M1 lowers SVG (§9), which breaks each of those assumptions:

- SVG names are case-sensitive (`viewBox`, `linearGradient`). The HTML parser adjusts a fixed set
  of them in foreign content and lower-cases the rest, while a client's `setAttribute` keeps the
  case as written, so SSR and the client can disagree.
- The HTML parser leaves SVG when it meets `div`, `p`, `span`, `b` and other HTML tags, so an HTML
  element inside `<svg>` parses differently on the server and the client.
- Tag-keyed tables collide: SVG has its own `a`, `title`, `script` and `style`. An SVG `<title>`
  renders, where React hoists an HTML one.
- Svelte drops whitespace-only text everywhere in SVG except under `<text>`.
- Vue's template compiler gives a root `<path>` the HTML namespace, so a component whose root is an
  SVG child renders in the wrong namespace there.

## Decision

- **The namespace is derived, not stored.** `<svg>` starts the SVG namespace, and everything inside
  it is SVG. MathML stays UF1002, reported once with nothing inside analysed. `foreignObject` is
  UF1002 in M1.
- **Elements come from `SVG_ELEMENTS`** (`@unframework/ir`): the vendored JSX SVG list that Vue's
  `isSVGTag` also knows, minus hyphenated, deprecated and unrenderable names, checked against
  parse5's tag adjustments; every entry matches the tag pattern. `script`, `style`, `foreignObject`,
  `animate`, `animateMotion`, `animateTransform`, `set` and `discard` are unrenderable in SVG
  (UF3002 or UF1002): SMIL can set an `href` at run time, and animation breaks visual determinism.
  An HTML element inside `<svg>` is UF3001; an SVG-only element outside it is UF3001 with help. A
  component whose root is an SVG child (`<g>`) is UF1002 until M3.
- **Attributes are case-exact**, from a table checked against parse5's attribute adjustments and the
  vendored `SVGAttributes`. `class`, `id`, `style`, `tabindex`, `lang`, ARIA and `data-*` work as in
  HTML. SVG has no boolean attributes, so a bare SVG attribute is UF3004. `xlink:href` is UF3004
  with a safe fix to `href` when `href` is not set; other `xlink:`, `xml:` and `xmlns` names are
  UF3005. The URL rules apply to SVG's `href`.
- **Text in SVG.** Whitespace-only text is UF3003 with a safe removal fix, except under `text`,
  `tspan` and `textPath`. An Interpolation may sit only in `text`, `tspan`, `textPath`, `title` and
  `desc` (UF3003).
- **Printing.** A childless SVG element self-closes in every output (`<circle … />`). Bound SVG
  attributes follow ADR-0037, and numbers in an SVG `style` follow `UNITLESS_PROPERTIES`
  (ADR-0038), so `strokeWidth: 2` is UF3018 with a fix to `"2"`; the `stroke-width="2"` attribute
  is unaffected.
- **The capability `svg`** (any `svg` element) is native on all seven targets.
- **Amendments to ADR-0032.** A tag is an HTML element, or, inside `<svg>`, an `SVG_ELEMENTS`
  entry; HTML elements never sit inside `<svg>`. An attribute is an HTML attribute of its element
  or, in SVG, one from the SVG tables, with no `true` value. Whitespace-only text appears in SVG
  only under the text elements. The schema's tag and attribute-name patterns accept upper case; the
  case-exact tables, checked by the invariants, decide what is valid.

```tsx
<svg viewBox="0 0 24 24" role="img" aria-labelledby="icon-title">
  <title id="icon-title">{label}</title>
  <circle cx="12" cy="12" r="10" stroke-width="2" />
</svg>
```

## Consequences

**Positive:**

- Inline icons, the common SVG in components, render the same DOM, in the SVG namespace, on seven
  targets, from SSR and from the client.
- The tables are tested against parse5, Vue and the vendored types, so a new SVG name is a table
  change with an oracle, not a guess.

**Negative:**

- `foreignObject`, SMIL animation, MathML and a component rooted in an SVG child are not available
  in M1.
- Whitespace between SVG elements must be left out of the source: formatted JSX keeps none anyway,
  but hand-written spaces are rejected.

**Open:**

- M3: SVG-child roots, which need the parent's namespace to reach the child's output.
- `foreignObject` needs the namespace to switch back to HTML in every printer and in the
  invariants.

## Alternatives considered

- **A stored `namespace` field on elements.** Targets would not re-derive it, but it is redundant
  with the tree, and an invariant would have to check that the two agree (P5: a field only when a
  consumer needs it).
- **Accept `xlink:href` beside `href`.** Two spellings of one attribute (P3); frameworks differ on
  `setAttributeNS`, and the normaliser compares attribute namespaces.
- **Lower-case SVG names as HTML does.** `viewBox` would then fail on every client that keeps case.

## Evidence

- Svelte 5.57.1 removes whitespace-only text in SVG unless a `text` element is an ancestor
  (`can_remove_entirely` in its transform utilities).
- React 19.3 hoists nothing in SVG context, so an SVG `<title>` renders in place.
- parse5 8.0.1's foreign-content tables (`SVG_TAG_NAMES_ADJUSTMENT_MAP`, the SVG attribute
  adjustments and `causesExit`) are the oracle for the tag and attribute tables and for the HTML
  elements that break out of SVG.
- Vue's `isSVGTag` lists `font-face`, `missing-glyph` and `color-profile`, which do not fit the tag
  pattern and are left out.
- Qwik 2.0.0-beta.47 renders `style={{ strokeWidth: 2 }}` as `stroke-width:2px`; React and Vue
  render `stroke-width:2`.
- ADR-0031's `normalizeDom` throws on an SVG child created in the HTML namespace, so a target that
  gets the namespace wrong fails L7.
- `jsx/svg` is green at every live layer on all seven targets (to verify in M1).
