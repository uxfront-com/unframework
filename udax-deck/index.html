Agents now write most of the diff. The scarce work is deciding what to build, splitting it well, steering it, and checking what comes back.

Today that work is spread across four tools that don’t share context. People carry it between them by hand.

Six rules the design follows.

The issue is the unit of work.

Branches, worktrees, PRs, and agent runs hang off issues. Never the other way around.

Zoom is navigation.

One canvas runs from the portfolio to a line of code. No tabs to lose your place in.

Status is readable from any height.

Color and glyph survive every zoom level. You can read a project’s health at 8%.

Agents are teammates on the canvas.

They work where you can see them and talk in the issue’s conversation. A person always owns the outcome.

Proposals are ghosts until accepted.

Anything an agent suggests is visibly unconfirmed, free to drop, and never runs on its own.

Approve by evidence.

Review starts with “does it meet the criteria?” and only then “is the diff good?”

Branching out. Agents propose, you prune.

Press S on any issue and an agent drafts sub-issues as ghosts. Ghosts cost nothing, run nothing, and vanish unless you keep them.

  • Every ghost explains itself: why it exists, which repos it touches, and a rough size.
  • Keep or drop in one key. ↵ accepts, E edits, ⌫ drops, ⇧↵ keeps all.
  • Dropped ghosts are remembered as out of scope for this project, so they don’t come back.

One issue, many repositories.

Features cross service boundaries. An issue owns one branch name, created in every repo it touches, each in its own worktree.

  • Repos are inherited. Sub-issues start with the parent’s repos and narrow them down.
  • Worktrees are automatic. Created when work starts and removed after merge, so parallel agents never share a checkout.
  • Contracts are checked across repos. A type change in api flags every PR that depends on it.

Multi-repo work ships as one changeset.

When an issue spans repos, its PRs merge together in dependency order. One preview runs every branch at once, so you test the feature, not the fragments.

Waiting
  • Order comes from the graph. Dependencies and contract checks decide what merges first. You can reorder, and UDAX warns when that breaks a contract.
  • Each step rebases on the last one and reruns its checks against what just merged.
  • A failure pauses the train. Nothing else merges until a person chooses to revert or fix forward.

Agents work in the open.

No separate chat window. You see agents where they work, and you talk to them in the issue’s conversation.

  • Live agents glow cyan and narrate their current step on the node.
  • Needs you goes to the owner as a beacon on the node, visible from every altitude. Tab jumps to the next one. Answer inline without opening anything.
  • Collisions show up before conflicts. When two agents edit the same file, a coral link appears with one-click fixes.

Nouns first, then verbs.

Every command follows one grammar, so people and agents can guess the next one. Tables for reading, JSON for scripts, and nothing wakes an agent by surprise.

Grammar and conventions adapted from the Multica CLI (multica.ai/docs/cli).

Keys, not IDs.

CHK-32 works in every command. --full-id prints the UUID when a script needs it.

Tables for people, JSON for machines.

list prints a table and get prints JSON. --output switches either one.

Names resolve.

--to wren matches agents and people by name. --to-id settles a clash.

Long text goes through stdin.

--content-stdin and --content-file keep comments and descriptions out of shell quoting.

Side effects are announced.

A command that starts a run says so. --note and --no-start change things without waking an agent.

Runs get scoped tokens.

Inside a run, the runtime injects a token for that agent and issue. Human commands like login are refused.

Readable without color. Usable without a mouse.

  • Shape carries status. Dashed, empty, half, three-quarters, full. Color is a second channel, never the only one.
  • An outline view mirrors the canvas. ⌘\ switches to a tree that screen readers announce as a tree, with dependencies read out on focus.
  • Every canvas action has a key, and focus is always visible on the canvas.
  • Contrast is checked on the canvas ink. Text meets 4.5:1. Status inks and edges meet 3:1.
  • Reduced motion is respected. Beacons stop pulsing and become a static ring. Camera moves become cuts.
