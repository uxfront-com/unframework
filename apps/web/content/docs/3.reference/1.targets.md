Unframework compiles each component to seven targets. Each one writes a component in its framework's own format, and imports nothing but its framework.

| Target  | File                 | Component                                                   |
| ------- | -------------------- | ----------------------------------------------------------- |
| React   | `ProductTile.tsx`    | A function component                                        |
| Vue     | `ProductTile.vue`    | A single-file component with `<script setup lang="ts">`     |
| Svelte  | `ProductTile.svelte` | A component in runes mode, with `<script lang="ts">`        |
| Angular | `product-tile.ts`    | A component class with signal inputs and an inline template |
| Solid   | `ProductTile.tsx`    | A function component                                        |
| Qwik    | `ProductTile.tsx`    | A `component$`                                              |
| Astro   | `ProductTile.astro`  | A component with its props in the frontmatter               |

[Props](/docs/components/props) shows the seven files for one component.

## Capabilities

A capability is a feature a component can use: a kind of node, a kind of attribute, or something a framework does at run time. Each target declares, for every capability, how it supports it:

- **native**: the framework has the feature, and the output uses it;
- **emulated**: the output adds a small inline helper, named in the cell, because the framework lacks the feature;
- **unsupported**: the framework renders the feature differently, or not at all. The compiler reports [UF4001](/docs/reference/diagnostics#UF4001) at the feature's first use, with the target's reason, and the cell sets its severity.

So a difference between frameworks is declared here, never found only in a test.

The cells that are not native:

- **React, `class-binding`**: React's `className` takes one string, so an inline helper, `cx`, joins the static names, toggles and dynamic parts.
- **React, `event-once`**: React has no once listener, so a guard, `useOnce`, remembers each element the listener ran for, as `{ once: true }` removes a listener from its own element only.
- **React, `event-semantics`**: where React's synthetic event differs from the DOM's (`change` on a text field, a checkbox or a radio, `select`, `beforeinput`, a `wheel` or touch listener that is not passive, the events React has no prop for, and `focus` or `blur` beside a native `focusin` or `focusout`), the element's ref callback, declared once, listens natively, through `listen`.
- **React, `next-tick`**: React has no `nextTick`, so a hook, `useNextTick`, asks for a render at the priority of the code that calls it, and resolves once React has rendered it, run its effects and rendered what the component's watchers wrote. After a click's or a key's handler it resolves in the event's task, as on Vue; after a watcher's write, in an effect, in a timer or after an `await`, in a later task ([Semantics](/docs/reference/semantics#outside-the-contract)). It resolves when the component unmounts too.
- **Svelte, `event-once`**: a once listener's handler goes through an inline wrapper, `once`, whose guard is set when the handler first runs, never the DOM's `{ once: true }`: Svelte's `on` runs the handlers it delegated below the element inside its own listener, so the option would be used up by an event one of them stopped.
- **Solid, `class-binding`**: Solid's `class` takes one string, so an inline helper, `cx`, joins dynamic parts with the static names and toggles. Static names and toggles alone print as `class` and `classList`.
- **Solid, `interactivity`**: state, derived values, listeners and hooks are Solid's own. Solid runs what a write triggers as the write is made, so a watcher goes through an inline helper, `createWatcher`, and a `watchEffect` through `createWatchEffect`, over a scheduler: `createReaction` queues a watcher when a value it read is written, and a microtask runs each queued watcher once, those before the DOM updates first, with Vue's previous value, change test and cleanup timing. Client code is copied as written, with no `batch`: the watchers, not the writes, keep the contract's timing.
- **Solid, `next-tick`**: Solid applies writes to the DOM as it makes them, and the watchers run in a microtask queued at the first write, so an inline `nextTick` resolves a promise.
- **Angular, `event-capture`, `event-once` and `event-passive`**: a template's `(event)` binding takes no listener options, so the file declares an attribute directive for each event and option, `[ufClickCapture]`, which listens with `Renderer2.listen` and emits the event again. A `once` listener beside another listener of its event on its element runs with it in one template listener, in attribute order, under a guard instead, `once(clickOnce, $event) && …`: a method that remembers the elements it ran for.
- **Angular, `use-id`**: Angular has no id API, so a module counter, `nextId`, makes each instance's ids, `uf-id-<component>-<n>`, as Angular Material makes its own.
- **Angular, `next-tick`**: Angular renders a change in a later task, so a private `nextTick` method renders the pending change itself in a microtask, `ApplicationRef.tick()`, as Vue does, and resolves after it.
- **Qwik, `event-once`**: Qwik's listeners have no `once`, so a module-level set of the elements a once listener ran for, `once<Event>`, is checked first in its handler, which also takes the element's `preventdefault:` and `stoppropagation:` attributes off after its first run, unless another listener of the element still needs them.
- **Qwik, `next-tick`**: Qwik has no public way to wait for a render, so `nextTick` resolves after the next task, by which time the render its writes scheduled, in a microtask, has run.
- **Qwik, `conditional-event-control`** (an error): Qwik runs a handler once its code has loaded, after the event is dispatched, so it runs `preventDefault()` and `stopPropagation()` apart, while the event is dispatched. A control at the top of a template listener runs on every event, as the element's `preventdefault:click`; one there under a test of the event alone, or after guard clauses on the event, runs in a `sync$` handler, which captures nothing. Qwik cannot run any other control at dispatch: one after another statement, in a block beside other statements, in an `else` or a `switch` case, after a test of state or of what a control changes (`event.defaultPrevented`), or in a function the listener calls anywhere but at its top. Nor can it run a `once` listener's control under a condition or on an element that listens to the event in both phases (a `sync$` handler cannot tell whether the listener already ran), a capture listener's control where an element of the component listens to the event in both phases (Qwik runs those capture listeners from the window), or a control in a local function that reads the component's state and that client code hands to `addEventListener` or calls outside a template listener. Make the control the first statement of the listener, or the only statement under an `if` that tests only the event, and keep a `once` listener's control unconditional; in a listener that client code adds, make the control in the listener itself, before it calls a local function. The keyboard handler of a list box, a `switch` on `event.key` with a control in each case, has no Qwik output ([Events](/docs/components/events#preventing-the-default)).
- **Qwik, `late-prop`** (a warning): Qwik subscribes a `useComputed$` or a task only to the props the component holds when it reads them. A derived value or a watcher that reads an optional prop the parent did not pass at mount, and passes later (a spread that gains the key), does not see it, though the template does. Pass the prop from the start, `undefined` while it has no value.
- **Vue, `listbox`** (an error): Vue's client sets `multiple` but not `size` before it inserts the options, so it selects the first option, as a drop-down does, where HTML selects none.
- **Astro, `interactivity`** (for information): Astro components render on the server only, and each render is a new instance: event handlers, template refs, watchers and lifecycle hooks never run, and state keeps its initial value. A test that relies on client code is skipped on Astro, and the parity matrix shows the skip with this reason.
- **Astro, `event-capture`, `event-once`, `event-passive`, `event-semantics`, `conditional-event-control` and `next-tick`** (for information): they refine `interactivity`, so the compiler reports `interactivity` alone, once, at the first listener, ref, watcher or hook.
- **Astro, `use-id`**: a counter on `Astro.locals`, `uniqueId`, which lives for one request, makes ids unique on the page and the same for every request.

Every other difference between the frameworks is either handled by the target that has it, or rejected for every target by the compiler, with a code that names the framework. [Attributes](/docs/components/attributes), [Templates](/docs/components/templates) and [Events](/docs/components/events) list them, and [Semantics](/docs/reference/semantics) states what every target guarantees at run time, and the differences that the compiler cannot see ([Outside the contract](/docs/reference/semantics#outside-the-contract)).

## Component events

A component declares its events with `defineEmits` ([Events](/docs/components/events#component-events)), and each target takes them in its framework's convention, keeping the event's name:

| Target  | A parent listens to `change` with | The listener receives                                                                              |
| ------- | --------------------------------- | -------------------------------------------------------------------------------------------------- |
| React   | the prop `onChange`               | the payload's members, as arguments                                                                |
| Vue     | `@change`                         | the payload's members, as arguments                                                                |
| Svelte  | the prop `onchange`               | the payload's members, as arguments                                                                |
| Angular | the output `(change)`             | nothing for an empty payload, the value for one required member, and a tuple for any other payload |
| Solid   | the prop `onChange`               | the payload's members, as arguments                                                                |
| Qwik    | the prop `onChange$`              | the payload's members, as arguments; the listener may run after the emit                           |
| Astro   | nothing                           | nothing: Astro components render on the server only, and emit nothing                              |

Angular's `output()` emits one value, so a payload of two members or more, or with an optional member, is a tuple of exactly the arguments the emit gives: `share: [path: string, note?: string]` emits `["a.txt"]` or `["a.txt", "Please review"]`. React, Solid and Qwik type their event props with an exported interface beside the props, `<Name>Events`, and Svelte joins them to its `Props` type. Angular declares an output for each event under the event's name, so where a setup binding has that name, the class renames its own member: a local function `save` that emits `save` becomes the method `onSave`, and a state `status` the signal `currentStatus`.

## The Angular host

Angular renders every component inside a host element, which wraps the template's root. The other frameworks render the root directly. Unframework gives each Angular component an element selector, `uf-` and its name in kebab case, and styles its host `display: contents`:

<!-- prettier-ignore -->
```ts [product-tile.ts]
@Component({
  selector: "uf-product-tile",
  host: { style: "display: contents" },
  preserveWhitespaces: false,
```

A consumer writes `<uf-product-tile>`, Angular's ordinary element syntax. `display: contents` keeps the host out of layout, so the component's geometry and pixels match the other targets', and its accessibility tree is the same. The template holds the whole render tree: a single root, the roots of a root fragment, and the conditionals and lists beside them all render inside the one host.

Attribute selectors, which make the consumer's own element the host, are deferred to M3, with composition. Until then:

- a component whose root must sit directly inside its parent, such as an `<li>` in a consumer's list or a `<tr>` in a consumer's table, cannot be written for Angular;
- fallthrough attributes and slots, which need the host or a helper directive, land in M3.

The decisions behind this page are [ADR-0010](https://github.com/uxfront-com/unframework/blob/main/docs/adrs/0010-angular-host-element.md), [ADR-0012](https://github.com/uxfront-com/unframework/blob/main/docs/adrs/0012-output-event-and-model-names.md), [ADR-0015](https://github.com/uxfront-com/unframework/blob/main/docs/adrs/0015-no-runtime.md), [ADR-0033](https://github.com/uxfront-com/unframework/blob/main/docs/adrs/0033-framework-rendering-differences-are-capabilities.md) and [ADR-0047](https://github.com/uxfront-com/unframework/blob/main/docs/adrs/0047-events-listeners-handlers-and-emits.md).
