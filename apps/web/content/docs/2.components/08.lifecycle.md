---
title: Lifecycle
description: onMounted runs once the component's DOM is in the document, onUnmounted when it is removed, and nextTick waits for the DOM to update. None of them runs on the server.
navigation:
  icon: i-lucide-hourglass

A component's setup runs before its DOM exists, and on the server too. `onMounted` runs code once the component's elements are in the document, and `onUnmounted` once they are removed. In client code, `await nextTick()` waits until the DOM shows the writes made before it. All three run in the browser only, on every target.

## onMounted

`onMounted(callback)` runs once, after the component's DOM is in the document. It can read an element through a template ref, write state and emit:

<!-- prettier-ignore -->
```tsx [ArticlePreview.uf.tsx]
import { defineEmits, onMounted, ref, useTemplateRef } from "unframework";

export interface ArticlePreviewProps {
  title: string;
  text: string;
}

export default function ArticlePreview({ title, text }: ArticlePreviewProps) {
  const emit = defineEmits<{ ready: [characters: number] }>();

  const body = useTemplateRef<HTMLParagraphElement>();
  const characters = ref(0);
  const counted = ref(false);

  onMounted(() => {
    const length = body.value?.textContent?.length ?? 0;
    characters.value = length;
    counted.value = true;
    emit("ready", length);
  });

  return (
    <article class="article-preview" aria-label={title}>
      <h2>{title}</h2>
      <p ref={body}>{text}</p>
      <p role="status">
        {counted.value ? `${characters.value} characters` : "Counting the characters"}
      </p>
    </article>
  );
}
```

    if (typeof part === "string") {

  title: string;
  text: string;

/** The scope attributes taken off each host, for the roots its component renders later. */
const scopes = new WeakMap<Element, string[]>();

/**
 * Gives a root node of its component the scope attributes the component's styled parents put on
 * its host (ADR-0063), and takes them off the host, which keeps only `display: contents`.
 */
@Directive({ selector: "[ufScope]" })
export class ScopeAttributes implements OnInit {
  readonly ufScope = input.required<HTMLElement>();
  private readonly element = inject<ElementRef<Element>>(ElementRef);
  private readonly renderer = inject(Renderer2);

  ngOnInit(): void {
    const host = this.ufScope();
    let names = scopes.get(host);
    if (!names) {
      names = host.getAttributeNames().filter((name) => name.startsWith("data-uf-"));
      for (const name of names) this.renderer.removeAttribute(host, name);
      scopes.set(host, names);
    }
    for (const name of names) this.renderer.setAttribute(this.element.nativeElement, name, "");
  }
}

::

- React writes an effect with an empty list of dependencies, which runs the callback once, in an effect event.
- Vue writes `onMounted`, Svelte and Solid `onMount`.
- Angular writes `afterNextRender` in the constructor: it runs once the view is rendered, in the browser only.
- Qwik writes `useVisibleTask$` with the `"document-ready"` strategy, so the task runs once the document is ready, not when the element scrolls into view.
- Astro drops the hook, and renders the state it starts with.

A hook never runs on the server, so every target's server render shows the state before it: "Counting the characters". The browser then shows the count. A new value for a prop does not run the hook again.

`onMounted` and `onUnmounted` take an arrow function written in place: `onMounted(focusField)` is [UF2022](/docs/reference/diagnostics#UF2022), with a safe fix to `onMounted(() => focusField())`. They are called at the top level of the setup ([UF2005](/docs/reference/diagnostics#UF2005)), never inside a condition or another hook.

## onUnmounted

`onUnmounted(callback)` runs once the component is removed. It stops what the component started, such as a timer held in a setup `let`:

<!-- prettier-ignore -->
```tsx [AutoRefresh.uf.tsx]
import { defineEmits, onUnmounted, ref } from "unframework";

export interface AutoRefreshProps {
  /** Milliseconds between two refreshes. */
  interval: number;
}

export default function AutoRefresh({ interval }: AutoRefreshProps) {
  const emit = defineEmits<{ refresh: [count: number] }>();

  const enabled = ref(false);
  let timer: ReturnType<typeof setInterval> | undefined;
  let refreshes = 0;

  function tick() {
    refreshes += 1;
    emit("refresh", refreshes);
  }

  function toggle() {
    if (enabled.value) {
      clearInterval(timer);
      enabled.value = false;
    } else {
      timer = setInterval(tick, interval);
      enabled.value = true;
    }
  }

  onUnmounted(() => {
    clearInterval(timer);
  });

  return (
    <section class="auto-refresh" aria-label="Auto-refresh">
      <button type="button" aria-pressed={enabled.value} onClick={toggle}>
        Auto-refresh
      </button>
      <p role="status">{enabled.value ? "Refreshing" : "Paused"}</p>
    </section>
  );
}

  useEffectEvent,
  useLayoutEffect,
  useRef,
  useState,

  /** Milliseconds between two refreshes. */
  interval: number;
}

  onRefresh?: (count: number) => void;
}

export interface AutoRefreshAttributes {
  className?: string;
  style?: CSSProperties;
}

export default function AutoRefresh({
  interval,
  onRefresh,
  className,
  style,
  ...attributes
}: AutoRefreshProps & AutoRefreshEvents & AutoRefreshAttributes) {
  const onRefreshRef = useRef(onRefresh);
  useLayoutEffect(() => {
    onRefreshRef.current = onRefresh;
  });

  const [enabled, setEnabled] = useState(false);

      setEnabled(enabledRef.current);

      enabledRef.current = true;

    clearInterval(timer.current);

      aria-label="Auto-refresh"
      style={style}

The timer's callback runs later, after renders that may have passed new props. /** Joins class names, and the keys of an object's truthy entries, into one `className`. */
function cx(...parts: unknown[]): string {
  const names: string[] = [];
  for (const part of parts) {
    if (typeof part === "string") {
      if (part) names.push(part);
    } else if (part && typeof part === "object") {
      for (const [key, on] of Object.entries(part)) {
        if (on) names.push(key);
      }
    }
  }
  return names.join(" ");
}

/**
 * Vue's `nextTick` for one component: the promise resolves once React has rendered the writes
 * made before it and run their effects, and `settled` says nothing they wrote waits to render;
 * in the task of a click or a key that wrote, as on Vue. It resolves when the component unmounts
 * too.
 */
function useNextTick(settled: () => boolean = () => true): () => Promise<void> {
  const pending = useRef<{ ticket: number; resolve: () => void }[]>([]);
  const tickets = useRef(0);
  const mounted = useRef(false);
  const [rendered, render] = useReducer(
    (last: number, ticket: number) => Math.max(last, ticket),
    0,
  );
  useEffect(() => {
    if (!pending.current.length) return;
    // Once every effect of the commit has run.
    queueMicrotask(() => {
      if (!settled()) {
        // What the component's effects wrote has yet to render, and may end where it was, when
        // React commits nothing: a render of its own makes the next look certain.
        tickets.current += 1;
        render(tickets.current);
        return;
      }
      const due = pending.current.filter(({ ticket }) => ticket <= rendered);
      pending.current = pending.current.filter(({ ticket }) => ticket > rendered);
      for (const { resolve } of due) resolve();
    });
  });
  useEffect(() => {
    mounted.current = true;
    return () => {
      mounted.current = false;
      queueMicrotask(() => {
        if (mounted.current) return;
        const due = pending.current;
        pending.current = [];
        for (const { resolve } of due) resolve();
      });
    };
  }, []);
  return () =>
    new Promise<void>((resolve) => {
      tickets.current += 1;
      const ticket = tickets.current;
      pending.current.push({ ticket, resolve });
      render(ticket);
    });
}

/** The scope attributes of the styled parents that render this component, for its root. */
function scopeAttributes(props: object): Record<string, ""> {
  const scope: Record<string, ""> = {};
  for (const key of Object.keys(props)) {
    if (key.startsWith("data-uf-")) scope[key] = "";
  }
  return scope;
}

Where those writes end where they were and React would commit nothing, it asks for one more render. It resolves a pending request when the component unmounts too. The component calls it after the states it checks and before every function that awaits it.
- Angular renders a change in a task of its own, so a private `nextTick` method renders the pending change itself in a microtask, `this.appRef.tick()`, and resolves after it (`next-tick`, emulated).

`nextTick` is a function, not a macro: client code calls it anywhere, a handler, a watcher's callback, a hook or a local function they call. The setup runs before any DOM exists, so it does not call `nextTick` ([UF2005](/docs/reference/diagnostics#UF2005)). It is called bare and awaited: `nextTick(callback)`, and `nextTick` passed or held as a value, are [UF2025](/docs/reference/diagnostics#UF2025), with a safe fix that awaits it where the function can become `async`. On Vue, Svelte, Solid and Angular the code after `await nextTick()` runs in the task that wrote, and on React after a click's or a key's handler; elsewhere it may run after the next event ([Semantics](/docs/reference/semantics#outside-the-contract)). An event's `preventDefault()` after `await nextTick()` comes too late ([UF3033](/docs/reference/diagnostics#UF3033)).

      {label.value}
    </p>
  );
}
```

Every target's server render reads "Checking the connection", and the browser then shows "Online" or "Offline". Vue runs an immediate watcher's first callback during the setup, on the server too, so that callback is held to what the server can run ([UF2013](/docs/reference/diagnostics#UF2013), see [Effects](/docs/components/effects#immediate-watchers-and-cleanup)). Every other effect and every hook runs in the browser only, on every target ([Semantics](/docs/reference/semantics#effects-are-client-only)).

## Not yet

- Whether a parent's hooks run before or after its children's is outside the contract ([Semantics](/docs/reference/semantics#outside-the-contract)).
- Vue's other hooks, such as `onBeforeMount` and `onUpdated`, are not part of the language ([UF2016](/docs/reference/diagnostics#UF2016)): watch the values that change instead.
- An `async` setup lands in M8.

The decision behind this page is [ADR-0048](https://github.com/uxfront-com/unframework/blob/main/docs/adrs/0048-effects-and-lifecycle.md).
