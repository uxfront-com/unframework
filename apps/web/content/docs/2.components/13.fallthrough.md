---
title: Fallthrough
description: Attributes, DOM listeners, class and style a component doesn't declare fall through to its root element, or to the element its rest is spread on.
navigation:
  icon: i-lucide-arrow-down-to-line
---

A parent often needs to reach the element inside a component it doesn't own: give a button an `id` that a label points at, describe it with `aria-describedby`, tag it for a test, listen to its `focus` or give it some margin. So what a parent passes a component, and the component doesn't declare, falls through to the component's root element. It's Vue's rule, and every target follows it.

This page walks you through it. We'll look at:

- the attributes that fall through, and the ones that don't
- the DOM listeners that fall through
- `class` and `style`, which merge with the root's own
- a component whose root is another component
- a ref on a component that exposes nothing
- `...rest`, which puts all of it on another element
- turning fallthrough off, and the components that can't take it

## What falls through

Let's start with the rule. A component declares its props, its models, its slots and the events it lists in `defineEmits`. Everything else a parent passes it falls through:

- **Attributes**, like `id`, `aria-*`, `data-*` or `type`, land on its root element.
- **Listeners** of DOM events, like `onClick` or `onFocus`, listen on its root element.
- **`class` and `style`** merge with the root element's own.

The root element is the one element the component renders at its top. A root that is a component passes all of it on to that component, which places it by the same rule.

A declared prop never falls through, so a prop named like an attribute stays a prop. Where the root element sets an attribute the parent passes too, the parent's value wins. `key` is no attribute, and a `ref` holds the root element ([Refs](#refs)).

Pass a prop by its own name. `aria-label` on a component that declares `ariaLabel` is [UF3035](/docs/reference/diagnostics#UF3035), with a fix to `ariaLabel`, since Vue would give it to the prop and the other targets would put it on the root element. The same goes for a model's name.

## Attributes

Here a parent passes a button an `id`, two ARIA attributes, a test id and a `type`. The button declares only `title`:

<!-- prettier-ignore -->
```tsx [SaveButton.uf.tsx]
// Declares one prop, `title`, which it renders as text: a declared prop never falls through.
export default function SaveButton({ title }: { title: string }) {
  return (
    <button type="button" class="button">
      {title}
    </button>
  );
}
```

<!-- prettier-ignore -->
```tsx [Editor.uf.tsx]
import { ref } from "@uxfront/unframework";

import SaveButton from "./SaveButton.uf.tsx";

export default function Editor() {
  const pressed = ref(false);
  return (
    <div class="editor">
      <p id="save-hint">Saves the draft.</p>
      <SaveButton
        title="Save"
        id="save"
        aria-describedby="save-hint"
        aria-pressed={pressed.value}
        data-testid="save-button"
        type="submit"
        class="primary"
      />
      <button type="button" onClick={() => (pressed.value = !pressed.value)}>
        Toggle
      </button>
    </div>
  );
}
```

`title` is a prop `SaveButton` declares and renders as text, so it never reaches the `<button>` as an attribute. Everything else lands on the `<button>`: the `id`, the ARIA attributes, the `data-testid` and the `type`, where the parent's `submit` wins over the button's own `button`. The bound `aria-pressed` follows `pressed` as it changes. The corpus records the rendered DOM this way, with each text node in quotes:

<!-- prettier-ignore -->
```html
<div class="editor">
  <p id="save-hint">
    "Saves the draft."
  </p>
  <button aria-describedby="save-hint" aria-pressed="false" class="button primary" data-testid="save-button" id="save" type="submit">
    "Save"
  </button>
  <button type="button">
    "Toggle"
  </button>
</div>
```

The parent checks each attribute as one of that element's own, so the element's rules hold: HTML's names, the values an enumerated attribute allows and ARIA's ([Attributes](/docs/components/attributes)). A name that is no prop of the child and no attribute of its root element is [UF3035](/docs/reference/diagnostics#UF3035), with a fix to the closest prop or attribute, like `type` for `tpye`.

::

- React types what falls through as the root element's own props without the declared ones, `SaveButtonAttributes`, and the root spreads the props' rest, `{...attributes}`, after its own attributes, so the parent's win. A parent writes them in React's spelling for that element, like `className` or `tabIndex`.
- Vue passes them on by itself, as its own `$attrs`.
- Svelte types the props with the root element's attributes from `svelte/elements`, without the component's own names, and the root spreads the props' rest, `{...attributes}`, last.
- Angular has no attribute spread, and a host element that carries an attribute isn't unwrapped ([The Angular host](/docs/reference/targets#the-angular-host)). So each component declares two more inputs: `ufAttributes`, a record of attributes by name, and `ufListeners`, a record of listeners by event. The parent binds them on the host, `[ufAttributes]="{ id: 'save', … }"`, which keeps no attribute. The root binds an inline attribute directive, `Fallthrough` (`[ufFallthrough]`), which sets and removes the attributes through `Renderer2`, on the server and in the browser, the parent's winning ([`fallthrough`](/docs/reference/targets#capabilities), emulated). Where the root binds an attribute of its own that the parent passes too, like `[attr.aria-label]`, it binds the parent's value whenever the record holds that name, so the parent's still wins after the root's own value changes. A hand-written Angular parent that writes `id="save"` on `<uf-save-button>` puts it on the host, so it binds `[ufAttributes]="{ id: 'save' }"` instead.
- Solid takes the declared props out with `splitProps`, and the root spreads the others after its own attributes, so the parent's win.
- Qwik types the props with the root element's own, `Omit<PropsOf<"button">, …>`, and the root spreads the props' rest last.
- Astro spreads the rest of `Astro.props` last on the root. Astro writes every attribute it is given and the browser [keeps the first of two](https://html.spec.whatwg.org/multipage/parsing.html#parse-error-duplicate-attribute), so the root tests whether the parent passed each of its own attributes, `"type" in Astro.props ? type : "button"`. The parent's value wins whenever it passes the key, even as `undefined`, which removes the attribute, as Vue does. A bare boolean attribute Astro doesn't know, like `multiple`, passes on as `""`, so the element writes it bare.

So every output but Vue's types and spreads what falls through on each component with one root element, and you'll see it on every page of these docs, even where no parent passes anything. The rest the root spreads also carries a styled parent's `data-uf-*` scope attribute, so the parent's stylesheet reaches the root ([Styles](/docs/components/styles#the-childs-root)).

## Listeners

Next, let's look at listeners. Here a parent listens to a chip's `click`, `focus` and `keydown`, and to `pick`, the one event the chip declares:

<!-- prettier-ignore -->
```tsx [Chip.uf.tsx]
import { defineEmits } from "@uxfront/unframework";

// Declares one event, `pick`, which its own click emits: a consumer's `onClick` is a native
// listener beside it.
export default function Chip({ label }: { label: string }) {
  const emit = defineEmits<{ pick: [label: string] }>();
  return (
    <button type="button" class="chip" onClick={() => emit("pick", label)}>
      {label}
    </button>
  );
}
```

<!-- prettier-ignore -->
```tsx [Picker.uf.tsx]
import { ref } from "@uxfront/unframework";

import Chip from "./Chip.uf.tsx";

export default function Picker() {
  const log = ref<string[]>([]);

  function record(line: string) {
    log.value = [...log.value, line];
  }

  return (
    <section aria-label="Picker">
      <Chip
        label="Ada"
        onClick={(event) => record(`click on ${(event.currentTarget as Element).localName}`)}
        onPick={(label) => record(`pick ${label}`)}
        onFocus={(event) => record(`focus on ${(event.currentTarget as Element).localName}`)}
        onKeydown={(event) =>
          record(`keydown ${event.key} on ${(event.currentTarget as Element).localName}`)
        }
      />
      <ol aria-label="Log">
        {log.value.map((entry, index) => (
          <li key={index}>{entry}</li>
        ))}
      </ol>
    </section>
  );
}
```

`onClick`, `onFocus` and `onKeydown` aren't events `Chip` declares, so they're native listeners on its `<button>`, typed as that element's own would be: the `onKeydown` handler receives a `KeyboardEvent`. Where the root listens to the same event itself, both run, the root's own first, as Vue merges them. Each of the parent's listeners logs its event's `currentTarget`, the element it listens on. So tab to the chip, press `a` and click it, and the log reads "focus on button", "keydown a on button", "pick Ada" and "click on button": the listeners are on the `<button>` itself, not on an element around it.

An `onX` that is neither an event the child declares nor a DOM event is [UF3036](/docs/reference/diagnostics#UF3036), with a fix to the closest event, one the child declares or a DOM event, like `onClick` for `onClik`. A listener option on a listener that falls through, like `onClickOnce`, is [UF1002](/docs/reference/diagnostics#UF1002).

export interface ChipEvents {
  onPick?: (label: string) => void;

  label,
  onPick,

  onClick,
  ...attributes

    <button
      type="button"

    </button>
  );
}

- React takes the parent's `onClick` out of the props' rest and calls it from the root's own handler, after it emits `pick`. That handler takes the event type React gives the prop, so the parent's handler gets the same event. React's `onFocus` also hears focus that moves inside an element, so the parent's React output checks `event.target` to keep the DOM's `focus`. A listener whose React prop wouldn't keep the DOM's meaning on that element is [UF1002](/docs/reference/diagnostics#UF1002) on React: `change` on a text field, `focusin`, `focusout`, `select` and `beforeinput`.
- Vue merges the parent's listener with the root's own by itself.
- Svelte takes `onclick` out of the props' rest and calls it from the root's own handler, after its own code.
- Angular's parent binds `[ufListeners]="{ click: …, focus: …, keydown: … }"` on the host, and `Fallthrough` adds each listener with `Renderer2.listen` in the browser, after the element's own.
- Solid takes `onClick` out with `splitProps` and calls it from the root's own handler, after its own code.
- Qwik passes the root an array of both, `onClick$={[$(() => onPick$?.(label)), onClick$]}`, which runs the root's own first, and the parent's `event.currentTarget` reads Qwik's second parameter, the element. Where the root listens in the capture phase or passively, the parent's listener stays out of that group, so it runs in the bubble phase and its `preventDefault()` works. A `preventDefault()` at the top of the parent's listener runs in a `sync$` handler, not as a `preventdefault:` attribute, since a root that listens from the window would apply that attribute to the event anywhere on the page.
- Astro renders on the server only, so no listener runs: the output drops it, and the compiler reports it for information ([`interactivity`](/docs/reference/targets#capabilities)).

## Class and style

Now let's look at `class` and `style`. A component with one root element takes them like any attribute it doesn't declare, and the parent passes them as it would to an element, static or bound:

<!-- prettier-ignore -->
```tsx [Tag.uf.tsx]
export default function Tag({ label }: { label: string }) {
  return (
    <span class="tag" style="padding: 2px 6px; color: rgb(30, 30, 30)">
      {label}
    </span>
  );
}
```

<!-- prettier-ignore -->
```tsx [Tags.uf.tsx]
import { ref } from "@uxfront/unframework";

import Tag from "./Tag.uf.tsx";

export default function Tags() {
  const active = ref(false);
  return (
    <div class="tags">
      <Tag label="plain" />
      <Tag label="wide" class="wide" style="margin-left: 8px" />
      <Tag
        label="toggled"
        class={["picked", { active: active.value }]}
        style={{ color: active.value ? "rgb(200, 0, 0)" : undefined }}
      />
      <button type="button" onClick={() => (active.value = !active.value)}>
        Toggle
      </button>
    </div>
  );
}
```

Unlike the other attributes, they merge with the root's own rather than replace them. The root's class is the union of both sets of names: `tag wide`, or `tag picked active`. For a style property both set, the parent's declaration wins, and a property the parent sets to `null` or `undefined` is removed from the root, as an object merge does. So while `active` is false, the toggled tag has no `color` at all.

## Refs

A `ref` on a component that doesn't call `defineExpose` holds its root element, as Vue's `$el` does: through a chain of root components, and whatever `inheritAttrs` says. Type the ref as that element's DOM interface, by its name:

<!-- prettier-ignore -->
```tsx [NameField.uf.tsx]
import { onMounted, ref, useTemplateRef } from "@uxfront/unframework";

// Exposes nothing, so a ref on it holds its root element. Its own template ref on that element
// still holds it once mounted, beside the parent's: `onMounted` reads it, and its focus listener
// fills the field only if it did.
export default function NameField({ label }: { label: string }) {
  const input = useTemplateRef<HTMLInputElement>();
  const mounted = ref(false);
  onMounted(() => {
    mounted.value = input.value !== null;
  });
  function fill() {
    if (input.value && !input.value.value && mounted.value) input.value.value = "Ada";
  }
  return <input ref={input} name="name" aria-label={label} onFocus={fill} />;
}
```

<!-- prettier-ignore -->
```tsx [Bio.uf.tsx]

}

A ref of another type, or on a component whose root isn't one element, is [UF3046](/docs/reference/diagnostics#UF3046).

A component that exposes functions gives a ref those alone, never its element. So a ref through a root component that exposes functions is UF3046 too: it would hold those functions, which the component you put the ref on doesn't expose, and no element. ## Putting it on another element

Sometimes the root isn't the element a parent means. A text field's root is often a `<label>` around an `<input>`, and the `id`, the `placeholder` and the `focus` listener belong on the `<input>`. So a component can turn fallthrough to its root off with `defineOptions({ inheritAttrs: false })`, end its props pattern with a rest, `...rest`, and spread it whole on the element that should take it:

<!-- prettier-ignore -->
```tsx [Field.uf.tsx]
import { defineOptions } from "@uxfront/unframework";

// Turns fallthrough off and spreads what its consumer passes on its <input>, not on its root.
export default function Field({ label, ...rest }: { label: string }) {
  defineOptions({ inheritAttrs: false });
  return (
    <label class="field">
      {label} <input {...rest} name={label.toLowerCase()} />
    </label>
  );
}
```

<!-- prettier-ignore -->
```tsx [SignUp.uf.tsx]

export default function SignUp() {
  const focuses = ref(0);
  return (
    <form aria-label="Sign up">
      <p id="email-hint">We never share it.</p>
      <Field
        label="Email"
        id="email"
        aria-describedby="email-hint"
        placeholder="you@example.com"
        class="wide"
        style="margin-top: 4px"
        onFocus={() => focuses.value++}
      />
      <p>Focuses: {focuses.value}</p>
    </form>

```

`rest` holds exactly what would have fallen through to the root, its `class`, `style` and listeners included. So the `<input>` takes all of it, and the `<label>` keeps only its own class:

<!-- prettier-ignore -->
```html

  </p>

The parent checks what it passes against the `<input>`, or as SVG where the element is inside an `<svg>`, like a `<circle>`. The parent's value still wins over the element's own, wherever the spread sits. `rest` never holds a declared prop, and a styled parent's `data-uf-*` scope attribute stays on the root.

The rest has one canonical form, and one use. It needs `defineOptions({ inheritAttrs: false })`, or it is [UF2001](/docs/reference/diagnostics#UF2001), whose safe fix adds the call.

Its one use is a whole spread on one element outside any list. A member read like `rest.id`, a second spread, a spread in a list or a spread on a component is UF2001 too, since each target holds the rest its own way, and a member of it would mean something different on each. So is a spread inside a slot's fill, which the child may render many times, and a spread on `<component is>`, which chooses among several elements.

## A `<component is>` root

A component whose root is a [`<component is>` over tags](/docs/components/dynamic-components#as-a-components-root) takes what a parent passes as a one-element root does, on whichever tag renders: `class` and `style`, the attributes every tag takes, the DOM listeners and a ref. So does a component whose root component renders one. Here `Base` renders a link with an `href` and a button without one, and `Primary` renders `Base`:

<!-- prettier-ignore -->
```tsx [Base.uf.tsx]
// Its root is a `<component is>` over tags: a link with an `href`, and a button without one. It
// declares no `id`, ARIA, `data-*` or `title`, no listener and exposes nothing, so a consumer's
// attributes, listeners and ref fall through to whichever tag renders (ADR-0122). Its own `title`
// gives way to a consumer's, and its own click listener runs before a consumer's.
export default function Base({
  href,
  disabled,
  text,
}: {
  href?: string;
  disabled?: boolean;
  text: string;
}) {
  // A consumer handles a click, as a router would: the link does not navigate.
  function press(event: MouseEvent) {
    event.preventDefault();
  }
  return (
    <component
      is={href ? "a" : "button"}
      href={href}
      disabled={disabled}
      class="base"
      title="Base"
      onClick={press}
    >
      {text}
    </component>
  );
}
```

<!-- prettier-ignore -->

What falls through reaches the child whole, and the child chooses its tag as it renders, so an attribute falls through only where every tag takes it: `id`, `title`, `tabindex`, `aria-*` and `data-*`, with `type` on a link or a button. One that only some tags take, like `disabled`, which `<a>` doesn't take, is [UF1002](/docs/reference/diagnostics#UF1002): declare it as a prop and set it on the `<component is>`, which renders it only on the tags that take it. One that no tag takes is [UF3035](/docs/reference/diagnostics#UF3035).

A ref holds the element that renders, so type it as the union of the tags' DOM interfaces, in any order: `useTemplateRef<HTMLAnchorElement | HTMLButtonElement>()`. Tags that share an interface, like `h2` and `h3`, give it once, `HTMLHeadingElement`. A ref typed as one tag's interface, or as a supertype such as `HTMLElement`, is [UF3046](/docs/reference/diagnostics#UF3046).

::

Angular writes each tag in an `@case` of its own, and each tag's element binds the `Fallthrough` directive and holds the `ufElement` ref. Qwik writes a `<component is>` with listeners of its own as one element per tag, and each takes the rest. React and Solid hand the ref to whichever tag renders through a callback, since each tag types its `ref` for itself. Astro renders on the server only, so a listener that falls through is dropped, with [UF4001](/docs/reference/diagnostics#UF4001) for information.

## Where nothing can fall through

A parent that passes a component something it doesn't declare has it rejected rather than dropped ([UF3045](/docs/reference/diagnostics#UF3045)) where the component has no element to take it: it turns fallthrough off and spreads no rest, or its root is a fragment, a conditional or a list, a `<component is>` whose `is` reads a setup value, whose tags the parent can't read, or a root component that takes nothing itself. Pass what the child declares, spread its props' rest on one of its elements, or give it one root element.

A [`<component is>`](/docs/components/dynamic-components) whose candidates are components passes them `class` and `style` only. Anything else that would fall through to a candidate is [UF1002](/docs/reference/diagnostics#UF1002), so pass what every candidate declares, or render each by its own tag.
