---
title: Dynamic components

Sometimes the element itself depends on the data: a heading whose level follows its depth in an outline, a section title that drops a level when it is nested, a card that collapses into a chip. `<component is>` renders one of a set of tags, or one of a set of components, chosen by a condition or by a prop.

## Choosing a tag

`is` takes a conditional whose branches are tag names. The attributes and children apply to whichever tag renders:

<!-- prettier-ignore -->
```tsx [Section.uf.tsx]
import { ref } from "unframework";

export default function Section({ title }: { title: string }) {
  const nested = ref(false);
  return (
    <article>
      <component is={nested.value ? "h3" : "h2"} class="title">
        {title}
      </component>
      <button type="button" onClick={() => (nested.value = !nested.value)}>
        {nested.value ? "Lift" : "Nest"}
      </button>
    </article>
  );
}
```

::framework-switcher

#react

<!-- prettier-ignore -->
```tsx [Section.tsx]
import { type CSSProperties, useRef, useState } from "react";

export interface SectionAttributes {
  className?: string;
  style?: CSSProperties;
}

export default function Section({
  title,
  className,
  style,
  ...attributes
}: { title: string } & SectionAttributes) {
  const [nested, setNested] = useState(false);
  const nestedRef = useRef(nested);
  const Tag = nested ? "h3" : "h2";

  return (
    <article className={className} style={style} {...scopeAttributes(attributes)}>
      <Tag className="title">{title}</Tag>
      <button
        type="button"
        onClick={() => {
          nestedRef.current = !nestedRef.current;
          setNested(nestedRef.current);
        }}
      >
        {nested ? "Lift" : "Nest"}
      </button>
    </article>
  );
}

/** The scope attributes of the styled parents that render this component, for its root. */
function scopeAttributes(props: object): Record<string, ""> {
  const scope: Record<string, ""> = {};
  for (const key of Object.keys(props)) {
    if (key.startsWith("data-uf-")) scope[key] = "";
  }
  return scope;
}
```

#angular

<!-- prettier-ignore -->
```ts [section.ts]
import { Component, input, signal } from "@angular/core";

@Component({
  selector: "uf-section",
  host: { "[attr.class]": "null", "[attr.style]": "'display: contents;'" },
  preserveWhitespaces: false,
  template: `
    @let title = this.title();
    @let nested = this.nested();
    <article [class]="this.class()" [style]="this.style()">
      @switch (nested ? "h3" : "h2") {
        @case ("h3") {
          <h3 class="title">{{ title }}</h3>
        } @case ("h2") {
          <h2 class="title">{{ title }}</h2>
        }
      }
      <button type="button" (click)="onClick()">{{ nested ? "Lift" : "Nest" }}</button>
    </article>
  `,
})
export default class Section {
  readonly title = input.required<string>();
  readonly class = input<string>();
  readonly style = input<Record<string, string | null | undefined>>();
  protected readonly nested = signal(false);

  protected onClick() {
    this.nested.set(!this.nested());
  }
}
```

```tsx [Section.tsx]
import { type JSX, createSignal } from "solid-js";
import { Dynamic } from "solid-js/web";

export default function Section(
  props: { title: string } & { class?: string; style?: JSX.CSSProperties },

  const [nested, setNested] = createSignal(false);
```

```astro [Section.astro]
---

  title: string;

}

const { title, class: className, style } = Astro.props;

const nested = false as boolean;

```

::

- React, Qwik and Astro hold the chosen tag in a constant, `const Tag = nested ? "h3" : "h2"`, and render `<Tag>`.
- Vue writes `<component :is>`, Svelte `<svelte:element this={…}>`, and Solid `<Dynamic component={…}>`.
- A strict Angular template can't choose an element by value, so Angular writes an `@switch` with one `@case` per tag, each with the attributes and children ([`dynamic-component`](/docs/reference/targets#capabilities), emulated).

Every attribute must be valid on every candidate, since any of them may render: an attribute one tag doesn't take is [UF3006](/docs/reference/diagnostics#UF3006), for that tag.

A prop typed as a union of tag names can choose the tag too, as a heading's level:

<!-- prettier-ignore -->
```tsx [Heading.uf.tsx]
export default function Heading({ tag, text }: { tag: "h1" | "h2" | "h3"; text: string }) {
  return (
    <component is={tag} class="heading">
      {text}
    </component>
  );
}
```

## Choosing a component

The candidates can be components instead, imported or of the same module. Each one must declare every prop, model and slot you pass:

<!-- prettier-ignore -->
```tsx [Tag.uf.tsx]
import { ref } from "unframework";

import Card from "./Card.uf.tsx";
import Chip from "./Chip.uf.tsx";

export default function Tag({ label }: { label: string }) {
  const compact = ref(true);
  return (
    <section aria-label="Tag">
      <component is={compact.value ? Chip : Card} label={label} />
      <button type="button" onClick={() => (compact.value = !compact.value)}>
        {compact.value ? "Expand" : "Compact"}
      </button>
    </section>
  );
}
```

React, Qwik and Astro hold the chosen component in a constant, Vue writes `<component :is="compact ? Chip : Card">`, Svelte a `$derived` component, Solid `<Dynamic>`, and Angular an `@switch` with a `@case` per component. An attribute or a fill that one of the candidates doesn't declare is [UF3035](/docs/reference/diagnostics#UF3035) or [UF3038](/docs/reference/diagnostics#UF3038), as on any component.

## A known set

`is` chooses from a set the compiler knows when it compiles: a conditional or a literal whose leaves are all tags or all components, or a prop typed as a union of tag literals. Angular writes every candidate, and the typed targets check each one, so a value only the run time knows, such as a string from an API, is [UF3044](/docs/reference/diagnostics#UF3044), and so is a set that mixes tags and components. Write the candidates out in a conditional, or type the prop as a union of tags.

The decisions behind this page are [ADR-0054](https://github.com/uxfront-com/unframework/blob/main/docs/adrs/0054-composition-on-every-target.md) and [ADR-0055](https://github.com/uxfront-com/unframework/blob/main/docs/adrs/0055-composition-ir-capabilities-and-codes.md).
